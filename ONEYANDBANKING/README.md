# 货币银行学笔记库

本目录是《货币银行学》（易纲、吴有昌，第二版）逐章阅读过程中的问答沉淀。
笔记按信息密度分为**要点、卡片、综述**三层：简短记忆点按章归总，长篇或被引用的问答独立成卡，跨章卡片簇成熟后手写专业综述。
目标不是复刻对话，而是让每个问题可独立定位、可链接、可在“章节骨架”与“主题骨架”之间自由切换。

## 目录结构

```
ONEYANDBANKING/
├── README.md                  # 本文件：使用规范 + 模板 + 整理Prompt
├── 00-导论/
│   ├── index.md               # 本章问答地图 + 教材页码索引
│   ├── 要点集.md              # 本章简短记忆点归总
│   ├── 名义变量与实际变量.md   # 卡片：长篇或被引用的问答
│   └── ...
├── 01-货币与利率/
│   ├── index.md
│   ├── 要点集.md
│   └── ...
├── ...
└── 综述集/                    # 跨章节专业综述，满足规则 B 后创建，不放占位文件
    └── ...
```

## 三层笔记体系

| 层级 | 载体 | 承载内容 | 晋升条件 |
|---|---|---|---|
| **要点** | 各章 `要点集.md` | 1–3句可自足的简短记忆点 | 被其他笔记引用前，先晋升为卡片 |
| **卡片** | 独立 Markdown 文件 | 需要展开机制对比、口径拆解或失效边界的问答，或将被引用的问答；五节模板，「核心逻辑」可充分展开 | 同一主题 ≥3 张跨章卡片 + 一句中心论点 |
| **综述** | `综述集/` 独立文档 | 专业文档式总结梳理，论证与增量 | — |

### 规则 A：笔记分层与卡片晋升

笔记按信息密度与引用需求分为两级：**要点**与**卡片**。
篇幅超过一屏、或被其他笔记引用的问答，建立独立卡片文件，沿用五节模板；
1–3 句可自足的简短记忆点，收录于所在章节的 `要点集.md`，以三级标题分隔，不强制拆分。
要点在被引用前须先晋升为卡片（**先拆后引**），保证全库链接粒度统一为文件级。

### 规则 B：主题成熟与综述创建

跨章联系先通过卡片「关联」小节互链，**不建占位文件**。
当同一主题积累 **≥3 张跨章节卡片**、且可提炼出**一句中心论点**时，在 `综述集/` 下新建**综述文档**（`type: synthesis`）：
按“摘要 → 概念界定 → 分析框架 → 分论点论证 → 争议与存疑 → 参考卡片”的专业文档结构撰写，不再使用问答体。
论证与增量写在综述中，事实与细节以链接指向卡片，**不复制正文**；
卡片更新后若影响综述结论，将综述标记为 `stale`。

## 记录原则

### 1. 问题即标题，不改为名词短语

每张卡片的 `#` 标题尽量还原为当时提出的**真实问题**，而非事后概括的名词短语。
“名义变量和实际变量怎么区分”比“名义变量与实际变量的定义”更能唤起当时的认知缺口。
（综述例外：标题用“主题名：中心论点”。）

### 2. 不保留对话回合结构

笔记不是聊天记录。不写“你问—我答—你再问—我再答”。
用自己的话重新组织：先给结论（要义），再给分析框架（核心逻辑），再给例子（例证），最后处理遗留问题（辨析存疑）。

### 3. 例子做减法，不做加法

对话中的例子往往铺陈较长。笔记中每个例子控制在1–2句，只保留**对比结构**和**关键数字**。
如果某个例子在对话中占了很长篇幅但核心洞察只有一句，笔记里就只留那一句。
减法针对单个例子的铺陈，不限制例子数量；一个机制若需多个案例从不同侧面印证，可列3–4个，每个仍控制在1–2句。

### 4. 公式保留，推导从简

核心关系式（如 $MV=PY$、$i \approx r + \pi$）保留，但推导过程不必逐步入库。
笔记的读者是“三个月后复盘的我”，不是“正在学推导的我”。

### 5. 章节归属以“主要问题域”为准

一个问题如果横跨多章，主文件放在**它最核心地回应了哪一章的问题**之下，其他章用链接指过来。
不为每个交叉点建重复文件。跨章联系先以卡片「关联」互链，满足规则 B 后在 `综述集/` 建综述。

### 6. `index.md` 是每章的“收口动作”

每章阅读告一段落时，更新该章 `index.md` 的表格：问题、笔记链接、教材位置。
表格只列**值得回头跳查的卡片**；要点不入表，统一见本章 `要点集.md`。

### 7. 元数据用 frontmatter，不塞进正文

`source`、`pages`、`tags`、`status` 放在 YAML frontmatter 中。
正文里不反复出现“（见第3章 p.87）”，页码信息在 frontmatter 里保留一次即可。

### 8. 状态标记用于复盘筛选

- `draft`：刚整理，未复核
- `current`：内容自洽，可引用
- `stale`：教材后续章节、新政策或所引卡片更新使其部分过时，待更新

综述文档另用 `type: synthesis` 标记，并以 `cards` 字段登记所引卡片。

## 文件命名规范

- 用中文，简洁，能一眼看出“这个问题问的是什么”
- 不用日期前缀（排序由文件夹和 index 决定）
- 不用序号前缀（章节文件夹已经提供了顺序）
- 固定文件名：每章 `index.md`、`要点集.md`；综述以主题命名
- 示例：`名义变量与实际变量.md`、`宏观杠杆率的口径拆解.md`、`数量型与价格型调控的转型条件.md`

## 链接规范

- 笔记之间用 `[[文件名]]` 双链
- 指向综述用 `[[综述集/杠杆率]]`（仅链接已存在的综述；未成熟主题用卡片互链）
- `index.md` 中用标准 Markdown 表格链接，便于在 GitHub 上直接点击
- **禁止链接到共享文件的标题锚点**（如 `[[要点集#某条目]]`）：要点被引用前先拆为卡片，再链接卡片文件

tags: [{2–4个标签}]
status: draft
created: {当天日期，格式 YYYY-MM-DD}
---

> **要义**：{一两句话，一般不超过150字；标准是不读正文也能独立成立，保留“是什么+为什么重要”的完整逻辑链}

## 分析价值

{可选。区分/辨析/口径类问题填写：不做这个区分会犯哪类错误？

{卡片主体。定义→关系式→传导链条；机制对比、口径拆解、失效边界值得展开。
多口径或多功能对比优先用表格，不压缩成段落。公式用 $...$ 包裹。}

## 例证

- **{例子名称}**：{同上}

{例子数量2–4个。减法针对单个例子的铺陈，不限制例子总数。}

## 辨析存疑

{易混概念、当时卡住的点、后续复盘意识到的问题。没有则写“暂无”。}

模板不是枷锁：内容简单时允许省略小节，比强行填满更诚实。

## 提炼原则

1. 标题用原问题，不用名词短语。
2. 不保留“你问—我答”的回合结构，按上述五节重组。
3. 例子做减法：每个例子1–2句，只留对比和关键数字；减法针对单个例子的铺陈，不限制例子总数。
4. 公式保留，推导从简。
5. 对话中重复强调的内容，在“要义”和“核心逻辑”中各出现一次即可，不反复堆叠。
6. 如果对话涉及具体政策、数据、案例，保留可核查的关键事实（时间、机构、数字），但不保留对话中的修饰性铺陈。
7. 不确定的页码留空，不编造。

## 表达层去特征化约束

1. 禁止反问与设问：把答案直接写成第一句话，不用问题制造悬念。
2. 禁止否定平行与对照框架：直接写肯定陈述；需要说明常见误解时，用“常见误解是 X；正确的是 Y”，不用“不是……而是……”。禁止用“过去……现在……”作组织线索。
3. 禁止结尾升华与金句收束：最后一个知识点陈述完毕直接结束，停在事实性表述上。
4. 禁止元话语与自我注解：删除“值得注意的是”“需要强调的是”“本文将……”等不携带实际信息的过渡壳。
5. 禁止三连排比与同构短句连排：保留信息量最大的一句，其余用不同句式分别陈述。
6. 保真优先：上述约束与术语、公式、数值、条件限定的准确性冲突时，保真优先。
